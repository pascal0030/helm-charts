# infinidysk Helm Chart

This Helm chart deploys [infinidysk](https://www.infinidysk.com/) on Kubernetes with flexible configuration options for development and production environments.

infinidysk is a Usenet-backed virtual filesystem. Sonarr, Radarr and other Arr apps add it as a SABnzbd download client; nothing is downloaded to disk. Your media server reads the files over the built-in FUSE mount or WebDAV, and infinidysk streams them from your Usenet providers on demand.

> **infinidysk 2.x is in beta.** Variable names, value formats and defaults may change between beta releases. The chart tracks the 2.x image `ghcr.io/infinidysk/infinidysk-next`; 1.x keeps the `ghcr.io/infinidysk/infinidysk` image and is not what this chart is written for.

---

## Installing the Chart

To install the chart with the release name `my-infinidysk`:

```bash
helm install infinidysk https://pascal0030.github.io/helm-charts/
```

To install with custom values:

```bash
helm install infinidysk https://pascal0030.github.io/helm-charts/ -f my-values.yaml
```

To uninstall/delete the `infinidysk` deployment:

```bash
helm uninstall infinidysk
```

Open the service on port `3000` and create the admin account **before** the service is reachable from an untrusted network: until an admin exists, anyone who reaches the page can create one.

## Requirements

The built-in FUSE mount (`mount.fuse: true`, the default) needs the node to provide:

- `/dev/fuse`, mounted into the container as a `CharDevice`
- the `SYS_ADMIN` capability
- an unconfined AppArmor profile (`containerSecurityContext.appArmorProfile.type: Unconfined`, Kubernetes 1.30+)
- a root user in the container, so the process may mount; file ownership inside the mount follows `config.puid` and `config.pgid` instead

If your cluster does not allow that (a restricted Pod Security Standard, for example), set `mount.fuse: false` and serve the library over WebDAV only. You can then drop the capability and the AppArmor profile and run as an unprivileged user.

## Settings

infinidysk keeps its settings in its database and they are edited in the web UI. Any setting can be forced with an environment variable, which is how this chart manages them declaratively. Give `config.settings` the setting paths from the [environment variable reference](https://www.infinidysk.com/v2/reference/environment/); the chart turns `performance.preset` into `INFINIDYSK__PERFORMANCE__PRESET` for you.

Lists and objects may be written as plain YAML — the chart renders them as the JSON infinidysk expects:

```yaml
config:
  settings:
    performance.preset: max_playback
    network.public_url: https://infinidysk.example.com
    sab.categories:
      - tv
      - movies
    imports.library_dirs:
      - path: /data/media
```

A forced setting shows in the UI as **Set by environment** and cannot be changed there. Removing it from the values and upgrading brings the saved value (or the default) back.

Settings that carry secrets belong in `config.secretSettings`. They land in the chart's Secret and reach the container through `envFrom`, so they are not written into the pod spec:

```yaml
config:
  secretSettings:
    providers:
      - id: 0190f6c4-0000-7000-8000-000000000001   # a fixed UUID keeps provider stats across restarts
        profile: newshosting
        username: my-user
        password: my-password
        max_connections: 50
    arr_instances:
      - id: 0190f6c4-0000-7000-8000-000000000002
        name: Sonarr
        profile: sonarr
        url: http://sonarr:8989
        api_key: my-sonarr-key
```

To keep secrets out of your values entirely, point `auth.existingSecret` at a Secret whose keys are the `INFINIDYSK__…` variable names, or set `config.useExternalSecret: true` and let [External Secrets](https://external-secrets.io/) build that Secret from your secrets manager.

## Example: Basic Installation

Create a `values.yaml` file:

```yaml
persistence:
  enabled: true
  size: 50Gi

config:
  timezone: Europe/Zurich
  settings:
    network.public_url: https://infinidysk.example.com
```

Install the chart:

```bash
helm install my-infinidysk charts/infinidysk -f values.yaml
```

## Example: PostgreSQL

Point infinidysk at an existing PostgreSQL database instead of the SQLite file in `/config`:

```yaml
config:
  database:
    existingSecret: infinidysk-postgresql
    existingSecretKey: database-url
```

The Secret holds a `postgres://user:password@host:5432/database` URL. `/config` still holds the metrics store, the logs and the saved repair data, so keep persistence on.

## Sharing the mount

By default the FUSE mount only exists inside the pod, which is enough when your media server reads the library over WebDAV or runs in the same pod. To make the mount visible on the node and in other pods, enable the host mount:

```yaml
mount:
  hostPath:
    enabled: true
    path: /mnt
    mountPath: /mnt
    mountPropagation: Bidirectional

containerSecurityContext:
  privileged: true
```

Kubernetes only allows `Bidirectional` mount propagation for privileged containers, and the chart refuses to render without it. Other pods bind the same host path with `HostToContainer`.

## Gateway API (HTTPRoute) support

The chart supports configuring a Kubernetes Gateway API HTTPRoute via the `route.main` values. Use this to attach an HTTPRoute to one or more Gateways.

- `route.main.enabled`: enable HTTPRoute creation (default: false)
- `route.main.hostnames`: list of hostnames the HTTPRoute should match.
- `route.main.parentRefs`: list of Gateway parentRefs (each may include `name`, `group`, `kind`, and `namespace`). If `namespace` is omitted the release namespace is used.

Example:

```yaml
route:
  main:
    enabled: true
    hostnames:
      - infinidysk.my-domain.com
    parentRefs:
      - name: cilium-gateway
        group: gateway.networking.k8s.io
        kind: Gateway
        namespace: kube-system
```

Ensure the Gateway API CRDs and a compatible Gateway controller (for example Cilium Gateway) are installed in your cluster.

## Metrics

infinidysk exports Prometheus metrics itself, so there is no exporter sidecar. `metrics.enabled` turns on `/metrics` on the service port, behind the admin API key. The ServiceMonitor sends that key as a bearer token: set `auth.apiKey` and the chart wires its own Secret up, or point `metrics.serviceMonitor.bearerTokenSecret` at a Secret of your own.

```yaml
auth:
  apiKey: my-admin-api-key

metrics:
  enabled: true
  serviceMonitor:
    enabled: true
```
